## Why Is ESLint Yelling at Me?

Before ICS 314, I thought coding standards were mostly about keeping code organized and making it look nice. I never really thought they could help me become a better programmer. After using ESLint with TypeScript, I can see that coding standards are useful for more than just formatting.

My first experience with ESLint has been both helpful and a little annoying. Sometimes I think my code is finished, but ESLint still finds something that needs to be fixed. Since TypeScript is new to me, though, these errors have helped me notice mistakes and learn how the language is supposed to be written.

I also understand why coding standards are important when working with other people. Code should not only work; it should be easy for someone else to read and understand. Following the same standards makes everyone's code more consistent and easier to work with.

Overall, I still don't love fixing every ESLint error, but I think it has helped me improve my coding habits. It makes me pay more attention to how I write code instead of only caring about whether it runs.
